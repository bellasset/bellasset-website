# 株式会社ベルアセット ホームページ（GitHub Pages 公開用一式）

このフォルダには、GitHub Pages でそのまま公開できる静的サイト一式が入っています。
Claude Artifact（プレビュー用のページ）は使用せず、HTML・CSS・JavaScript・画像をすべて
このリポジトリから直接配信する構成になっています。

---

## ⚠️ 公開の流れについて（重要）

このファイル一式には、ドメインがまだ確定していないため **実在しない仮のドメイン名**
`your-domain.example` を設定しています（`.example` は「実際には存在しないことが保証された、
説明用の予約ドメイン」です。誤って本物のサイトとして扱われることはありません）。

公開は、必ず以下の順番で進めてください（詳しい手順は下の「公開までの手順」に番号順で
記載しています）。

1. **正式なドメインを取得する**
2. **`your-domain.example` を、取得した正式ドメインへ一括置換する**
3. **`CNAME` ファイルの中身が、正式ドメインだけになっていることを確認する**
4. **GitHubへアップロードする**
5. **GitHub Pagesを有効化する**
6. **DNSを設定する**
7. **HTTPSを有効化する**
8. **Search ConsoleとGoogleビジネスプロフィールを設定する**

※ ドメインを取得する前に、GitHub Pagesの仮URL（`https://（ユーザー名）.github.io/（リポジトリ名）/`）
で表示だけを確認したい場合は、その時点では **`CNAME` ファイルをアップロードしないでください**。
`your-domain.example` が入ったままの `CNAME` をアップロードしてしまうと、GitHub Pagesが
存在しないドメインへ向けて公開しようとしてしまうためです。仮URLでの確認方法は、下記
「手順4」の中で説明しています。

## サイトの構成

```
index.html          … ホーム
business.html        … 事業内容・実績
company.html         … 会社概要
contact.html         … お問い合わせ
404.html             … ページが見つからない場合に表示されるページ
styles.css           … デザイン（黒とゴールドを基調）
script.js            … スマートフォン用メニューなどの動作
robots.txt           … 検索エンジン向けの設定
sitemap.xml          … 検索エンジンに送信するページ一覧
CNAME                … 独自ドメインの設定ファイル
assets/images/       … 写真・ロゴなどの画像
assets/favicon/      … ブラウザタブに表示されるアイコン（favicon）
```

正式URLは `https://（あなたのドメイン）/`（`www` なし）です。`www` 付きでアクセスした
場合は、こちらの正式URLへ自動的に転送されるよう、手順6でDNSを設定します。

## 公開までの手順（非技術者向け）

### 1. 正式なドメインを取得する

1. ドメイン登録サービス（例：お名前.com、ムームードメインなど）にアクセスします。
2. 希望するドメイン名（例：`bellasset.co.jp` のような形）を検索し、空いていることを確認します。
3. 各サービスの案内に従って登録・お支払いを行い、ドメインを取得します。

※ ドメインを取得するまでは、このあとの手順2・3は行わず、本一式は
`your-domain.example` が入ったままの状態にしておいてください。

### 2. `your-domain.example` を正式ドメインへ一括置換する

ドメインを取得したら、以下のすべてのファイルに含まれる `your-domain.example` を、
実際に取得したドメイン名へ置き換えます。

置き換えが必要なファイル：

- `CNAME`
- `index.html`（canonical・og:url・og:image・JSON-LD 内）
- `business.html`（canonical・og:url・og:image）
- `company.html`（canonical・og:url・og:image）
- `contact.html`（canonical・og:url・og:image）
- `sitemap.xml`（4件のURLすべて）
- `robots.txt`（Sitemapの行）

置き換え方法（非技術者向け・おすすめ）：

1. パソコンに [Visual Studio Code](https://code.visualstudio.com/)（無料）をインストールします。
2. このフォルダを Visual Studio Code で開きます（「フォルダーを開く」）。
3. 画面左のアイコンから虫眼鏡ではなく「検索」→「ファイル内を検索して置換」（Windowsは `Ctrl+Shift+H`、Macは `Cmd+Shift+H`）を開きます。
4. 検索欄に `your-domain.example`、置換欄に実際のドメイン（例：`bellasset.co.jp`）を入力します。
5. 「すべて置換」を押します。

### 3. CNAMEの中身が正式ドメインだけになっていることを確認する

1. `CNAME` ファイルを開きます。
2. 中身が実際のドメイン名だけになっていることを確認します（前後に余計な空白や
   `https://` を付けないでください）。

### 4. GitHubへアップロードする

**4-1. GitHubアカウントを作成する**

1. [https://github.com/](https://github.com/) にアクセスします。
2. 「Sign up」からメールアドレス・パスワード・ユーザー名を登録し、アカウントを作成します。
3. 登録したメールアドレスに届く確認メールの指示に従って、アカウントを有効化します。

**4-2. 公開リポジトリを作成する**

1. GitHubにログインした状態で、右上の「＋」→「New repository」を選びます。
2. リポジトリ名を決めます（例：`bellasset-website`）。
3. 「Public」（公開）を選択します。
4. 「Add a README file」にはチェックを入れずに「Create repository」を押します
   （このフォルダにすでに README.md が含まれているためです）。

**4-3. サイトファイル一式をアップロードする**

1. 作成したリポジトリのページで「uploading an existing file」（または「Add file」→
   「Upload files」）を選びます。
2. このフォルダの中身（`index.html` や `assets` フォルダなど、手順2・3で正式ドメインへ
   置き換え済みのもの）を**リポジトリの一番上の階層に**そのままドラッグ＆ドロップします
   （`bellasset-website` フォルダそのものではなく、中身のファイル・フォルダをアップロード
   してください）。
3. 画面下部の「Commit changes」を押してアップロードを確定します。
   ※一度に多くのファイルをアップロードできない場合は、数回に分けてアップロードしてください。

> ⚠️ ドメイン取得前に、GitHub Pagesの仮URLだけで表示を確認したい場合（手順1〜3をまだ
> 行っていない場合）は、`CNAME` ファイルだけをアップロードから外してください。
> `your-domain.example` が入ったままの `CNAME` をアップロードすると、GitHub Pagesが
> 存在しないドメインへ向けて公開しようとしてしまいます。この場合は、手順1〜3が終わって
> 正式ドメインに置き換わった段階で、あらためて `CNAME` をアップロードしてください。

### 5. GitHub Pagesを有効化する

1. リポジトリ画面の「Settings」タブを開きます。
2. 左側メニューの「Pages」を選びます。
3. 「Build and deployment」の「Source」で「Deploy from a branch」を選びます。
4. 「Branch」で `main`（または `master`）と `/ (root)` を選び、「Save」を押します。
5. しばらく待ち、GitHub Pagesの公開処理が完了したことを確認します。正式ドメインを
   記載したCNAMEをアップロード済みの場合、GitHubの仮URLは正式ドメインへ転送される
   ことがあります。DNS設定前は正式ドメインでサイトを表示できない場合があるため、
   この段階では公開処理の完了だけを確認し、実際の表示確認は手順6のDNS設定後に
   正式URLで行ってください。
6. `CNAME` ファイルを正式ドメインの内容でアップロード済みの場合、「Custom domain」の欄に
   実際のドメイン（例：`bellasset.co.jp`）が自動的に反映されていることを確認します。
   反映されていない場合は、この欄に直接入力して「Save」を押します。

### 6. ドメイン会社側でDNSを設定する

ドメインを取得した会社（お名前.com、ムームードメインなど）の管理画面で、以下のDNS
レコードを設定します。設定項目の名称は会社によって多少異なります（「DNS設定」「ネーム
サーバー設定」などの名称で操作できます）。

**正式URLを `https://（あなたのドメイン）/`（wwwなし）にするための設定：**

| 種類 | ホスト名 | 値 |
|---|---|---|
| A | @（または空欄／ドメインそのもの） | 185.199.108.153 |
| A | @（または空欄／ドメインそのもの） | 185.199.109.153 |
| A | @（または空欄／ドメインそのもの） | 185.199.110.153 |
| A | @（または空欄／ドメインそのもの） | 185.199.111.153 |
| CNAME | www | （GitHubのユーザー名）.github.io |

上記のIPアドレスはGitHub Pagesの公式ドキュメントに記載されている値です。設定前に
[GitHub Pagesの公式ドキュメント](https://docs.github.com/pages)で最新の値をご確認ください。

この設定により、`www.（あなたのドメイン）` でアクセスした人は、GitHub Pages側の機能で
自動的に `https://（あなたのドメイン）/`（wwwなし）へ転送されます。

DNSの設定が反映されるまで、数十分〜24時間程度かかることがあります。

### 7. HTTPSを有効化する

1. DNS設定の反映後、リポジトリの「Settings」→「Pages」を開きます。
2. 「Enforce HTTPS」のチェックボックスが選択できるようになったら、チェックを入れます
   （反映直後は選択できないことがあります。その場合は数時間待ってから再度確認してください）。
3. 実際にブラウザで `https://（あなたのドメイン）/` を開き、アドレスバーに鍵マークが
   表示され、警告なく表示されることを確認します。

### 8. Search ConsoleとGoogleビジネスプロフィールを設定する

**8-1. Google Search Consoleへドメインを登録する**

1. [Google Search Console](https://search.google.com/search-console) に、ホームページの
   管理に使うGoogleアカウントでログインします。
2. 「プロパティを追加」から「ドメイン」を選び、実際のドメイン名（例：`bellasset.co.jp`）を
   入力します。
   ※「URLプレフィックス」ではなく「ドメイン」を選ぶと、`www`あり・なし両方をまとめて
   管理できます。

**8-2. DNSのTXTレコードで所有者確認をする**

1. 8-1で「ドメイン」プロパティを追加すると、Google Search Consoleの画面に
   「このTXTレコードをDNSに追加してください」という指示と、**Google側が発行した
   固有の確認用の値**が表示されます。
2. この画面に表示された値を、ドメイン会社の管理画面でTXTレコードとして追加します
   （ホスト名は通常 `@` または空欄のままで構いません）。
   ※ここで使う値は本手順書には記載できません。Google Search Consoleの画面に表示される、
   お客様専用の値をそのまま入力してください。
3. ドメイン会社側でTXTレコードを保存したら、Google Search Consoleの画面に戻り
   「確認」ボタンを押します。DNSの反映に時間がかかる場合は、しばらく待ってから
   再度「確認」を押してください。

**8-3. sitemap.xmlを送信する**

1. Google Search Consoleの左メニューから「サイトマップ」を選びます。
2. 「新しいサイトマップの追加」の欄に `sitemap.xml` とだけ入力し、「送信」を押します。

**8-4. 4ページをURL検査してインデックス登録をリクエストする**

1. Google Search Console上部の検索欄に、以下の4つのURLを1つずつ入力して「URL検査」を
   行います。
   - `https://（あなたのドメイン）/`
   - `https://（あなたのドメイン）/business.html`
   - `https://（あなたのドメイン）/company.html`
   - `https://（あなたのドメイン）/contact.html`
2. それぞれの検査結果画面で「インデックス登録をリクエスト」を押します。
   ※反映まで数日〜数週間かかることがあります。

**8-5. Googleビジネスプロフィールへ公式サイトURLを登録する**

1. [Googleビジネスプロフィール](https://www.google.com/business/) にログインします
   （すでに事業者情報を登録済みの場合は管理画面を開きます）。
2. 事業者情報の編集画面で「ウェブサイト」の項目に `https://（あなたのドメイン）/`
   （正式URL）を入力し、保存します。

## 公開前の最終確認（チェックリスト）

- [ ] 390px・768px・900px・1024px・1280px の画面幅で、4ページとも横スクロールが
      発生しない
- [ ] `index.html`・`business.html`・`company.html`・`contact.html` の4ページすべてが
      直接開ける
- [ ] ブラウザの「戻る」「進む」が正しく動作する
- [ ] ナビゲーションのリンク切れがない（旧ファイル名やClaude ArtifactのURLへの
      リンクが残っていない）
- [ ] `sitemap.xml` と `robots.txt` がブラウザで直接開ける
- [ ] 各ページの `title` と `meta description` がすべて異なる内容になっている
- [ ] 各ページの `canonical` が実際の独自ドメインを指している（`your-domain.example`
      のままになっていない）
- [ ] `noindex` ・`nofollow` の指定が含まれていない（`404.html` を除く。404ページは
      検索結果に表示させないよう、意図的に `noindex` を設定しています）
- [ ] 構造化データ（JSON-LD）に構文エラーがない（[リッチリザルト テスト](https://search.google.com/test/rich-results)
      で確認できます）
- [ ] Claude Artifactの文字や共有用UIが表示されていない

## その他の注意事項

- 掲載している事業内容・実績・会社情報・写真は、現時点で確認できている内容のみを
  掲載しています。金額や物件情報などを新たに追加する場合は、確認済みの事実のみを
  掲載するようご注意ください。
- 画像は `assets/images/` フォルダにまとめてあります。差し替える場合は、同じ
  ファイル名で上書きするか、HTML内の `src` の指定を書き換えてください。
- デザインを変更する場合は `styles.css` を編集してください。
